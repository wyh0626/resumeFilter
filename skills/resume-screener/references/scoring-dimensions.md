# 六大评分维度详细标准

## 1. 技能匹配度 (权重: ⭐⭐⭐⭐⭐)

评估候选人掌握的技术栈与岗位JD要求的重合度。

### 评分标准

| 分数 | 标准 | 典型表现 |
|------|------|---------|
| 5 | 完美匹配 | JD中的核心技术栈100%覆盖，且有深度使用证据 |
| 4 | 高度匹配 | 覆盖80%以上核心技术栈，少量技能可快速补齐 |
| 3 | 基本匹配 | 覆盖60%核心技术栈，部分需要学习转换 |
| 2 | 部分匹配 | 仅覆盖40%以下，需要较多学习成本 |
| 1 | 严重不匹配 | 技术栈几乎完全不对口 |

### 评估要点

- **精确匹配**: 技能名称直接命中JD关键词（如JD要求Go，简历写Go）
- **等价匹配**: 技术本质相同但名称不同（如JD要求消息队列经验，简历写Kafka/RabbitMQ）
- **可迁移匹配**: 技术领域接近，迁移成本低（如JD要求Go，简历有Rust经验）
- **深度验证**: "精通"/"熟练"等自评是否有项目经历印证
- **版本关注**: 对于特定版本要求（如Java 17+、React 18+），检查是否匹配

### 注意事项
- 不要仅看技能列表，要交叉验证项目经历中的实际使用情况
- 区分"用过"和"深入使用"——项目中仅提及不等于熟练掌握
- 对于快速演进的技术（如前端框架），关注最近1-2年的使用记录

---

## 2. 项目经验相关性 (权重: ⭐⭐⭐⭐⭐)

评估候选人过往项目经验与目标岗位工作场景的相关程度。

### 评分标准

| 分数 | 标准 | 典型表现 |
|------|------|---------|
| 5 | 高度相关 | 有直接对口的行业+场景经验，解决过类似规模的问题 |
| 4 | 大部分相关 | 行业或场景有一项高度相关，另一项可迁移 |
| 3 | 部分相关 | 有可迁移的经验，但需要适应新场景 |
| 2 | 低相关 | 技术方向对口但行业/场景差距较大 |
| 1 | 不相关 | 过往经验与岗位需求几乎无交集 |

### 评估要点

- **行业匹配**: 候选人是否有目标行业经验（金融、电商、社交等）
- **场景匹配**: 是否处理过类似业务场景（高并发、大数据、分布式等）
- **规模匹配**: 候选人经历的系统规模是否与目标岗位匹配
- **角色匹配**: 过往担任的角色（IC/TL/架构师）是否与岗位要求吻合
- **时间权重**: 最近2-3年的经验权重最高

---

## 3. 成长潜力 (权重: ⭐⭐⭐⭐)

通过职业轨迹和简历中的信号评估候选人的发展潜力与学习能力。

### 评分标准

| 分数 | 标准 | 典型表现 |
|------|------|---------|
| 5 | 极强上升势头 | 职级持续上升，技术栈不断拓展，有突破性成果 |
| 4 | 良好成长 | 明显的职业发展轨迹，有能力提升的证据 |
| 3 | 稳定发展 | 有一定成长但速度平稳，无明显突破 |
| 2 | 发展缓慢 | 多年经验但职级/能力提升不明显 |
| 1 | 停滞/下行 | 职业倒退或长期停滞，缺乏学习信号 |

### 评估要点

- **职级轨迹**: 是否从初级→中级→高级持续晋升
- **责任范围扩大**: 从执行者→负责人→决策者的转变
- **技术栈演进**: 是否主动学习新技术，而非停留在舒适区
- **跨领域能力**: 是否展现多维度能力（如后端+数据+架构）
- **学历/培训**: 在职学习、专业认证等持续投入的信号

---

## 4. 影响力与深度 (权重: ⭐⭐⭐)

评估候选人在项目中展现的技术深度和影响范围。

### 评分标准

| 分数 | 标准 | 典型表现 |
|------|------|---------|
| 5 | 卓越影响力 | 有清晰量化成果，展现架构级技术决策能力 |
| 4 | 显著影响 | 大部分经历有量化成果，有独立技术判断 |
| 3 | 一般影响 | 部分经历有量化，但深度一般 |
| 2 | 较弱影响 | 缺少量化，多为执行层面描述 |
| 1 | 无影响力体现 | 纯职责描述，无成果展示 |

### 评估要点

- **量化成果**: 是否有具体的数字/百分比/指标改善
- **技术决策**: 是否展现方案选型、架构设计的决策能力
- **问题复杂度**: 解决的是简单任务还是复杂系统级问题
- **影响范围**: 成果影响个人/团队/部门/公司哪个层级
- **叙事深度**: 是"使用了XX"还是"为解决XX问题，在AB方案中选择A因为..."

---

## 5. 稳定性 (权重: ⭐⭐⭐)

评估候选人的职业稳定性和入职后的留任概率。

### 评分标准

| 分数 | 标准 | 典型表现 |
|------|------|---------|
| 5 | 非常稳定 | 每段经历2年以上，跳槽有清晰的上升逻辑 |
| 4 | 较稳定 | 大部分经历1.5年以上，偶有短期经历可解释 |
| 3 | 一般 | 平均每段1-1.5年，存在一定不确定性 |
| 2 | 偏不稳定 | 多段经历不足1年，缺乏合理解释 |
| 1 | 高风险 | 频繁跳槽（半年内），明显不稳定 |

### 评估要点

- **任职时长**: 每段工作的持续时间
- **跳槽逻辑**: 每次跳槽是否有合理的上升动机（薪资、职级、平台）
- **行业一致性**: 是否在同一领域深耕，还是频繁跨行业
- **当前状态**: 是在职还是离职？离职多久？
- **合理例外**: 公司倒闭、裁员潮、试用期不匹配等可理解的短期经历

### 注意事项
- 互联网行业的合理跳槽周期通常为1.5-3年
- 初创公司经历需特别考虑（公司生命周期短不等于候选人不稳定）
- 外包/合同制经历的短期性是行业特性，不应过度扣分

---

## 6. 加分项 (权重: ⭐⭐)

识别简历中能增强候选人竞争力的额外信号。

### 评分标准

| 分数 | 标准 | 典型表现 |
|------|------|---------|
| 5 | 多项强加分 | 知名开源贡献+技术博客+大厂核心团队+行业大会演讲 |
| 4 | 有明显加分 | 有1-2项显著加分项 |
| 3 | 有一定加分 | 有一些小的加分信号 |
| 2 | 无明显加分 | 简历中无额外亮点 |
| 1 | 不适用 | 无需评估（应聘初级岗位时此项可忽略） |

### 加分信号清单

| 类别 | 加分项 |
|------|--------|
| 技术影响力 | GitHub开源项目（关注Star数和活跃度）、技术博客、专利 |
| 行业认可 | 技术大会演讲、行业奖项、技术社区核心贡献者 |
| 教育背景 | 顶尖院校、相关专业、研究成果 |
| 公司背景 | 知名科技公司核心团队、明星创业公司 |
| 特殊经历 | ACM/竞赛获奖、创业经历、跨文化工作经验 |
| AI时代意识 | 展现利用AI工具提效的能力，关注技术前沿趋势 |

---

## 综合评分计算

加权平均公式：

```
综合评分 = (技能匹配度×5 + 项目相关性×5 + 成长潜力×4 + 影响力×3 + 稳定性×3 + 加分项×2) / 22
```

### 结论映射

| 综合评分 | 建议结论 |
|---------|---------|
| ≥ 4.0 | ✅ 强烈推荐，优先安排面试 |
| 3.5 - 3.9 | ✅ 推荐，安排面试 |
| 3.0 - 3.4 | ⚠️ 待定，视候选人池情况决定 |
| 2.5 - 2.9 | ⚠️ 偏弱，仅在候选人不足时考虑 |
| < 2.5 | ❌ 不推荐，与岗位要求差距较大 |

**注意**：综合评分仅供参考，任何单项存在致命红旗（如信息造假、硬性门槛不达标）应直接标记为❌，不受综合评分影响。
