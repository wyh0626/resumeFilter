# 红旗识别清单

## 🚨 致命红旗 (Deal Breakers) — 建议直接淘汰

| 红旗 | 识别方法 | 说明 |
|------|---------|------|
| 信息不一致 | 工作时间重叠、技术栈前后矛盾、职级描述冲突 | 诚信是底线，发现一处则全部存疑 |
| 明显造假嫌疑 | 不合理的数据（"个人优化系统QPS从100到100万"）、夸大的职级 | 严重诚信问题 |
| 硬性门槛不达标 | 学历、年限、必备资质/证书不满足JD明确要求 | 除非用户特别放宽，否则不可通融 |
| 严重语法/术语错误 | 技术术语拼写错误、基本语法问题 | 反映专业素养和严谨度 |

---

## ⚠️ 严重红旗 (Major Concerns) — 需在面试中重点验证

| 红旗 | 识别方法 | 面试验证建议 |
|------|---------|-------------|
| 频繁跳槽 | 3段以上工作经历不足1年，且无合理解释 | 直接询问每次离职原因 |
| 技能与项目脱节 | 技能栏写"精通Kubernetes"但项目中从未提及容器化 | 现场出技术深度题验证 |
| 纯职责描述 | 全是"负责XX系统开发"，无任何成果描述 | 追问"你做了什么，结果如何" |
| 玩具项目充数 | 大量课程项目或烂大街项目（见下方清单） | 追问项目用户量、线上问题 |
| 职业断层 | 超过6个月的空白期未说明 | 友好询问空白期活动 |
| 降级跳槽 | 从高级→中级，管理→IC，大厂→小厂（无合理解释） | 了解背后原因 |

---

## ⚡ 一般红旗 (Minor Issues) — 记录但不影响通过

| 红旗 | 表现 | 影响 |
|------|------|------|
| 摘要冗长/空洞 | 超过3行，充斥"热情"、"努力" | 简历写作水平一般 |
| 缺乏量化 | 无数字、百分比、具体指标 | 影响力不明确，需面试挖掘 |
| 格式混乱 | 日期格式不统一、排版零散 | 细节意识待改进 |
| 技能罗列过多 | 列出20+技能且无分级 | 核心能力不聚焦 |

## 玩具项目识别

### 明显的玩具项目特征

1. **烂大街项目**
   - XX外卖系统 / XX秒杀平台 / XX商城
   - XX博客系统 / XX在线教育平台
   - XX聊天室 / XX管理系统

2. **课程作业特征**
   - 没有真实用户数据或生产环境
   - 技术栈选择缺乏理由
   - 缺少上线、运维经历
   - 描述中无任何实际挑战

3. **验证问题**（面试时可追问）
   - "这个项目有多少用户？"
   - "你遇到过什么线上问题？"
   - "为什么选择这个技术栈？"

### 筛选建议
- 应届生/初级岗位：玩具项目可接受，但需看是否有深度思考
- 中高级岗位：玩具项目充数是负面信号

## 外包公司名单

以下公司经历需关注但**不应一票否决**，重点看候选人在其中的实际项目质量：

### 大型IT服务/外包
- 中科软、中软国际、法本信息、国通
- 洛道科技、软通动力、东软集团
- 文思海辉、博彦科技、柯莱特、易思博

### OD/外包性质
- 华为OD (Outsourcing Dispatch)
- 阿里外包、字节外包、腾讯外包

### 筛选评判原则
- 外包经历本身不扣分，但需重点验证：候选人在项目中的实际角色和贡献
- 如果做的是甲方核心项目，技术深度可能很好
- 从外包转正或跳到甲方是正向信号
- 长期（3年以上）纯外包且无技术深度提升是风险信号

## 职业断层评估

| 断层原因 | 风险等级 | 评估建议 |
|---------|---------|---------|
| 创业失败 | 低风险 | 可能是加分项，看收获和成长 |
| 读研/进修 | 无风险 | 正常学业规划 |
| Gap Year / 旅行 | 低风险 | 合理的个人选择 |
| 裁员 | 低风险 | 行业常态，尤其是大规模裁员潮期间 |
| 身体/家庭原因 | 低风险 | 属于个人隐私，不应深究 |
| 长期无说明 | 中风险 | 面试时需了解 |
| 多次断层 | 高风险 | 需综合评估整体稳定性 |
